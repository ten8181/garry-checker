# Garry’s Checker — GitHub Pages 実機テスト版

## 公開手順
1. GitHubで新しい公開（Public）リポジトリを作成します。例：garry-check。
2. ZIPを解凍し、中身をリポジトリ直下にアップロードします。index.htmlとiconsフォルダが同じ階層になるようにしてください。ZIPファイルそのものをアップロードするのではありません。
3. Settings → Pages → Deploy from a branch → main / (root) → Save。
4. Pages画面に表示されたHTTPSのURLをSafariやChromeで開きます。初回の公開には数分かかることがあります。
5. iPhoneのHTMLファイルプレビューではなく、公開URLで動作確認してください。ホーム画面への追加も公開URLから行います。

このZIPを受け取っただけでは公開されません。公開リポジトリ内のソースとスプレッドシートURLは誰でも読めます。秘密情報や個人情報は入れないでください。

## ファイル
index.html / style.css / app.js / sw.js / manifest.webmanifest / icons / FONT-LICENSE.txt。
index.html内のappConfigに初期スプレッドシートURLとカテゴリ・ステータスを設定しています。config.jsonは使用しません。

## スプレッドシート
初期設定はユーザーの公開専用シート（1nXNm-4yJaznSKlA3t9p3a8yngxPB4xjWA_MD6YUd4fk）、先頭タブです。読み取り専用で接続します。
1行目：ID | 日付 | 開始時刻 | 種別 | タイトル | メモ | 追加日時
開始時刻と追加日時は任意（列ごと省略しても可）。列名で判別するので列順は自由です。
日付はYYYY/MM/DD、開始時刻は00:00〜23:59（空欄可）。10/19 24:30のTV番組は、日付2026/10/20・開始時刻00:30・種別TVで入力します。
IDは重複なし・固定。公開後に変更・再利用すると個人の進捗との対応が崩れます。
シートのメモは公開される出演詳細であり、アプリ内の個人メモとは別です。
共有設定は「リンクを知っている全員：閲覧者」。非表示列や別タブも秘密情報の保管場所にはしないでください。

## NEW表示（追加後24時間）
- タイトル横に赤い「NEW」。Notion公開用マスターの「作成日時」を、GASでシートの「追加日時」へ渡す予定です（GASは別途設定）。
- 「追加日時」はプレーンテキストで、例 `2026-10-20T15:00:00.000Z` または `2026-10-21T00:00:00+09:00`。秒とタイムゾーン必須。GASでは文字列のまま保存してください。
- 追加日時から24時間未満だけ表示。24時間ちょうどで対象外。未来・無効・空欄の日時や列なしには表示しません。日付だけの値も使いません。
- ページを開いたままでも約1秒間隔で期限を判定し、復帰時にも再判定。出演日・状態・メモの編集ではNEWの期間を延ばしません。
- 端末の時計が判定基準です。閲覧開始時刻ではなく全員共通の追加日時を使います。
- 既存の6列シートにも対応。追加日時がまだない間は従来どおりで、NEWは付きません。
- 公開済みサイトに反映するには、この版のファイルをGitHubへアップロードしてください。

## 表示・操作
- 今日のGarry／過去のGarry／未来のGarry。TVのみ朝5時、それ以外は午前0時（日本時間）で日付を切り替えます。
- 未確認は過去の未完了を古い順、未来は近い順。各5件から「もっと見る」で5件ずつ追加表示。
- TV：まだだお／録画予約したお／見たお。雑誌：まだだお／予約・購入したお／読んだお。1件につき1状態を選択します。
- 完了カードは淡いグリーン。過去の完了記録は折りたたみ内。
- 個人メモは最大500文字。進捗と個人メモはブラウザ内だけに保存します。
- 起動時と下部の「再読込」でシートを取得します。開いたままのシート自動定期取得はありません（日付区分は自動更新）。
- 取得失敗時は同じ読み込み先の前回データがあれば表示。なければ3つの欄とも「情報を読み込めませんでした。」と表示します。詳細は下部「エラーの詳細」。

## 保存と移行
別端末・別ブラウザ間で自動同期されません。ブラウザのデータ削除やプライベートブラウズではデータが失われる場合があります。
下部「進捗の書き出し / 読み込み」からバックアップできます。読み込みは現在の進捗と個人メモを上書きします。
PCのfile://プレビューから公開URLへも自動移行しません。移したい場合は先に旧画面からバックアップを書き出し、公開URLの画面で読み込んでください。
読み込み先シートID・シート名・出演IDが保存データの識別に使われます。シート変更時に自動移行はしません。
Notionとシートの自動同期は未実装です。公開用マスターからシートへの転記は手動です。
カテゴリ設定はindex.html内appConfigを変更して再公開します。運用後の状態の並びや数の変更は避けてください。

## フィードバックとサイト更新履歴（次回公開用・未反映）
- ページ下部「フィードバック・要望を送る↗︎」からNotionの匿名フォームを新しいタブで開きます。名前・メール欄なし、自由記入1問のみ必須。
- フォームの案内：匿名で送れます。個人情報は書かないでください。個別のお返事はできません。
- 回答DBはサイトに埋め込まず、フォームへのリンクだけを設置します。DBの一般公開は不要です。
- 「サイト更新履歴」は下部の折りたたみ。出演・掲載情報の追加は載せず、機能追加・デザイン変更・不具合修正のみ記載します。
- 未公開の変更を公開済みとして記載しないでください。NEW表示・フォームリンク・更新履歴の追加は、実際のGitHub反映時に公開日と一緒に追記します。現在は確認済みの初回公開だけを記載しています。
- この変更ではZIPを新規作成せず、GitHubも更新していません。

## 個人メモの共有・コピー（次回公開用）
保存済みメモのあるカードに「メモを共有」、下部に「メモをまとめて書き出す」を設置。
プレビューから「共有メニューを開く」（メモなど送り先のアプリを選ぶ）か「文章をコピー」（別アプリを開いて貼り付ける）の2択です。スマホ中心のため個人メモの.txtファイル保存は設けません。
共有は利用者がボタンを押した時だけです。キャンセル時の自動コピーや管理者への送信は行いません。共有非対応時はコピーを案内し、コピー失敗時には文章を選択して手動コピーを案内します。
一括は現在読み込まれている項目のメモ全件が対象。カテゴリや未完了の絞り込みに関係なく日付順で出力します。出演日・時刻は画面と同じ放送日／24時表記です。
シートから消えた項目など現在読み込めない情報も含めた退避には従来のJSONバックアップを利用してください。文章の共有・コピーから進捗の復元はできません。
JSONバックアップの書き出し／読み込みはそのまま残します。iPhoneの共有先の実機確認は公開後に行います。

## 公開画面の管理項目
ファン向けの下部メニューからスプレッドシート設定への入口を削除。接続URLと既存の保存設定は維持しています。管理画面の権限制御を追加したものではありません。
「サイト更新履歴」は初期状態で閉じたdetails内に説明と履歴をまとめ、開いたときだけ表示します。

## 下部メニューの整理
保存の案内は「チェック・メモはこの端末に保存」、日時ラベルは「最終更新」。この日時はシートを最後に正常取得した時刻で、サイトのリリース日時ではありません。取得失敗時は成功時の日時を維持します。
入口は「再読込」「メモを共有・コピー」「バックアップ」。詳しい保存場所・データ削除の注意・復元時の上書き説明はバックアップ画面にまとめています。
バックアップ画面は「バックアップを保存」「バックアップから復元」の2操作。従来のJSON形式と互換です。

カテゴリ切り替えのTV・雑誌にもカードと同じ線画アイコンを表示。「過去のGarry」は従来どおり過去の未完了が対象で、古い順に表示します。

## 日付付きのサイト更新履歴
トグル内を日付別の白いカードに整理。日付・変更の見出し・箇条書きで表示し、新しい順に並べます。2026/10/20の初回公開と2026/10/21の更新は、公開GitHubのindex.htmlコミット日時（日本時間）と公開コードを確認して記載しました。履歴の日付はサイト更新日で、出演日やシートの最終取得時刻とは別です。
「チェック・メモはこの端末に保存されます。」は「メモを共有・コピー」「バックアップ」の次の行に配置します。
